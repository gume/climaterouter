# ClimateRouter issue tracker

## Resolved

- [x] Velair integration is there, but the amount of pause is wrong. This pause should be the same length as it is with the manual mode. So if there is 37 minutes left, then the pause should be adjusted for 37 minutes. Velair counts the duration from the receival of the command.
  Resolved in `74ef5c6` (0.8.9). `velair.pause` now receives `duration_minutes` computed from the manual
  deadline at the moment of the call (start, timer change, or restored session), so a session with 37 minutes
  left pauses Velair for 37 minutes. An infinite manual session still pauses Velair without a deadline.
- [x] Add soft/hard read-only modes for the underlying climates, both for schedule and manual control.
  Resolved in `b8430f6` (0.9.0); the manual level was removed again in 0.10.0 (see below). `read_only_mode`
  selects `off`/`soft`/`hard`; `soft` suppresses every underlying write while the proxy keeps the requested
  state, and `hard` mirrors the real underlying state and dismisses commands.
- [x] Support setups with only one climate (radiator or AC) while keeping all other features.
  Resolved in `b8430f6` (0.9.0). Either the radiator or the AC may be omitted (at least one is required); the
  route is fixed to the configured target and never falls back to an unconfigured one.
- [x] Support Chauffage by driving its pause switch while manual mode is active.
  Resolved in `b8430f6` (0.9.0). The generic `scheduler_pause_switch_entity_id` accepts a `switch` or
  `input_boolean` and is turned on/off with manual mode, independent of the scheduler.
- [x] Expose a general `off` preset that turns the climate off.
  Resolved in `b8430f6` (0.9.0). `off` is always exposed and follows the same manual-mode and scheduler
  semantics as an HVAC off command.
- [x] The release script fails when the tag it creates already exists.
  Resolved in `29fc2bf`. Local and remote tags are checked independently, a tag pointing at another commit is
  refused, and only missing tags are created/pushed, so reruns are idempotent.
- [x] With `--push`, the release script still ended with `fatal: tag 'v0.9.0' already exists` after publishing.
  Resolved in `41733d8` (0.9.1). The command preview executed the publish commands before the confirmation
  prompt and then ran them again; it now only prints, and the real commands run once after confirmation.
- [x] The read-only level should not be a setup option but a runtime selector, and manual mode should not have a
  separate read-only level.
  Resolved in 0.10.0. The schedule read-only level is now the runtime `select.<name>_read_only_mode` entity in
  Controls, so it can be changed after setup. The manual read-only setting, including soft/hard, is removed
  entirely; manual mode always accepts user writes and always defers scheduler/automation commands.
- [x] The scheduler pause switch should be invertible, so it can signal either free or busy.
  Resolved in 0.10.1. `scheduler_pause_switch_invert` flips the polarity: off (default) signals busy with on while
  manual mode is active; on signals free with the entity on while the schedule is in control.
- [x] The manual-signal inversion toggle has no label or hint.
  Resolved in 0.11.0. The form field is labelled "Invert the manual signal (on = schedule free)" and its hint
  explains both polarities.
- [x] The `off` preset should be optional and offer a detached mode that keeps ClimateRouter live.
  Resolved in 0.11.0. The new **Presets** section has `off_preset_enabled` (default on) and
  `off_preset_keeps_live_state` (default off). Detached mode stops the underlying climate but keeps the proxy in
  its last live state, copying the active target's mode, setpoint, fan and action so a scheduler that refuses to
  start while the climate is off can resume.
- [x] The manual-mode options still showed a raw `scheduler_pause_switch_invert` key, an unnamed **Presets**
  submenu, and bare `off_preset_*` fields.
  Resolved in 0.11.1. The installed 0.11.0 bundle already contained every label and hint; Home Assistant's
  frontend had cached the 0.10.0 config-flow translations, which lacked those keys. The labels are now clearer
  ("Pause switch polarity is inverted (on = schedule free)", "Offer the off preset", "Keep ClimateRouter on when
  the off preset is used") and the handover notes that a hard browser reload (Ctrl+Shift+R) is required after an
  update before judging config-flow strings.
- [x] With a detached `off` preset, turning the preset on while the underlying climate was already off copied the
  off state into ClimateRouter instead of keeping the proxy live.
  Resolved in 0.11.1. The decoupled hold now never copies an `off` state: it reuses the last live desired state
  (persisted across restarts) and falls back to the last known setpoint, presenting the proxy as heating.
- [x] Diagnostics showed an `active target` that looked like it was always `none`.
  Resolved in 0.11.1. `active_target` remains the target currently being driven and is intentionally empty when
  everything is off. Diagnostics, the `active_target` sensor attributes, and the proxy now also expose
  `route_target` (the active target, otherwise the pending target, otherwise the last routed target) so the last
  route is still visible while the system is off.
- [x] Manual mode did not switch on when the user made a change.
  Resolved in 0.11.1. A user setpoint, preset, heat/cool mode, turn-on, or direct VTherm change now starts manual
  mode. The baseline is seeded before the live-mode check, and a running target's mode is adopted when the stored
  baseline is still off, so the first move after a restart is not lost.
